# 憲章・鮮度ティア・実行環境の判断材料

Issue [#212](https://github.com/pero3dev/ai-agent-library/issues/212)。2026-10-03（日本時間）の提案です。以下は選択肢と推奨であり、採択した方針・変更した運用ではありません。記事の引退・統合、定期タスクの移行、解析の導入を実行しません。

## 判断の前提

公開正本の199記事と16系統の台帳を入力に、[記事リストと試算JSON](2026q4-tier-proposal.json)を作りました。基準HEADは `f3af9b045c3703a6540b68301f6ef25dd2690d9c` です。[公開観測の集計](../../../freshness-automation.md#公開観測の台帳)は、5件のコミット済みrunの部分観測と宣言範囲の完了を区別します。本文の更新日を観測日へ代用しません。[基準値](../../records/2026-10-03/maintenance-baseline.md)の制作成功率・維持工数・読者数はunknownのままです。

## 3層の具体案と同じ単位での試算

候補のコア70本はREADMEの「まず読む」「実務で使う」と、学習ルートA〜Cの基礎概念・設計・実装・評価の章、学習ロードマップ、プロンプトインジェクション、脅威モデルを含みます。スナップショット16本はケーススタディとLLM内部章、標準113本は残る記事です。全199本を一意に割り当てたリストをJSONに保持しました。章全体をコアへ含める広い案なので、オーナーが絞り込むこともできます。

| 層 | 記事数 | 目標周期の案 | 記事観測枠/年（記事数×365÷周期） |
| --- | ---: | ---: | ---: |
| コア | 70 | 14日 | 1,825 |
| 標準 | 113 | 90日 | 約458 |
| スナップショット | 16 | 365日 | 16 |
| 合計 | 199 | 層別 | 約2,299 |

現行の台帳は2系統が7日・14系統が42日なので、365日で約226系統観測/年です。1回1〜3系統なら理論上約76〜226回/年が必要です。これは記事数とは違う単位です。同じ台帳の各系統に所属する記事数へ `365/周期` を掛けると、重複所属を含む約4,945記事観測枠/年になります。3層案は一意の199記事なので、差の約2,646枠に重複整理の効果も含まれます。記事全文の確認時間や取得資料数は未計測です。

2026-09-10〜09-27（run_idのUTC日付、18日間）にコミット済みrunは5件あります。単純年換算は約101run/年ですが、コミットしない変更なし回・ローカルrunは含まれず、各runの部分観測も全系統の完了とは違います。現在の実績と必要226系統を直接引き算して不足を確定しません。公開台帳で完了範囲を記録し、最低4週間のrun数・系統数・実作業時間を測って再試算します。

スナップショットでも、法制度・廃止・脆弱性・誤った安全保証などの訂正は年次を待ちません。モデル・コーディングの重要な告知は別の週次検出経路を維持する案です。#199の期限検出は取りこぼしへの補助で、全ベンダー発表の網羅検証ではありません。採択後はtierの正本、既存registryとの対応、公開表示、例外の優先順位を別の実装単位で定めます。

## 追加データと取得方法

| 必要な情報 | 取得方法と期間 | 判断への使い方 |
| --- | --- | --- |
| 読者需要 | Issue Formsの誤り/要望を4週間、記事・読者目的・重要度で集計。解析導入は別判断 | コアを70本から絞るか、統合候補を選ぶ |
| 維持工数 | runごとに観測・編集・検証・CI待機の分数を4週間記録。個人の稼働時間の全文は公開しない | 観測枠を実時間へ変換し、周期・環境の負荷を試算する |
| 停止と遅延 | 公開観測台帳と週次検知Issueの欠測・周期超過を、理由付きで記録 | PC維持の実効性とクラウド移行の必要性を評価する |
| 学習成果 | 学習ロードマップの小課題について希望者の任意フィードバックを集計 | 図・音声・追加記事に投資する条件を決める |
| クラウドの条件 | 実行方式・認証・権限・月額上限・復旧手順を候補別に見積もる | PC継続と移行を費用・運用時間・失敗検知で比較する |
