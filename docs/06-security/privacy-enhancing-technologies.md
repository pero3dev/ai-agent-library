# プライバシー強化技術の概観

## この記事の目的

マスキングの先にあるプライバシー強化技術(PET: Privacy-Enhancing Technologies)— 仮名化・匿名化・差分プライバシー・連合学習・秘密計算 — の「**何が実務で現実的か**」の見取り図を持てるようになります。各技術の階層・成熟度・適用場面を理解し、「高度な技術より先にやること」を踏まえた選定の判断フレームを持ち帰れる状態を目指します。会話データの収集・マスキングの実装は [会話データの管理基盤](../05-operations/conversation-data-management.md) が正本で、本記事は**技術の見取り図**に絞ります。数理の詳解はせず、適用判断に必要な直感まで扱います。

## 対象読者

- 個人情報・機微データを扱う AI システムで、マスキングの先の選択肢を検討するセキュリティ・データ基盤担当
- 「差分プライバシー」「連合学習」などの語を目にするが、自社で現実的かを見極めたいテックリード

## 前提知識

- [会話データの管理基盤](../05-operations/conversation-data-management.md) — PII 検出・マスキング・保持/削除の実装(本記事はその先の技術の見取り図)
- [AI のためのデータガバナンス](../05-operations/data-governance-for-ai.md) — データの分類・オーナーシップ(何を守るかの前提)

## 本文

### 概要: 「高度な技術」の前に見取り図を

「プライバシーを守る = 差分プライバシーや秘密計算を導入する」と飛躍しがちですが、技術ごとに守る対象と前提が異なります。まず最小化・アクセス統制などの基本で満たせる要件を確認し、公開する統計や学習時の更新情報など、残る経路に合う技術を選びます。会話データの実装は [会話データの管理基盤](../05-operations/conversation-data-management.md) が正本です。

### 技術の階層

本記事では PET を次の層に整理します。導入時の検討項目を整理するための分類であり、下の技術ほど保護が強いという順位ではありません。

| 階層 | 技術 | 何をするか |
| --- | --- | --- |
| ①検出・マスキング | PII 検出・マスキング | 個人情報を見つけて隠す・置き換える |
| ②仮名化・匿名化 | 仮名化・匿名化 | 個人を特定できないよう加工する(再識別の限界あり) |
| ③統計的保護 | 差分プライバシー | 保護対象のデータの有無・変更による出力確率の差を制限する |
| ④分散学習 | 連合学習 | 生データを各所に置いて学習する。共有する更新情報の保護は別途必要 |
| ⑤秘密計算 | 秘密計算・TEE | データを暗号化・隔離したまま計算する |

- **①検出・マスキング**: 個人情報を検出して隠す・置き換えます([会話データの管理基盤](../05-operations/conversation-data-management.md))。検出漏れや文脈からの再識別はありうるため、これで要件を満たすかを用途ごとに確認します
- **②仮名化・匿名化**: 個人を特定できないよう加工します。ただし**再識別の限界**があります — 他のデータと突き合わせると個人が特定できてしまうことがあり、「匿名化したから安全」とは限りません
- **③差分プライバシー**: **差分プライバシー(differential privacy)**は、保護対象のデータだけが異なる 2 つのデータセット(隣接データセット)で、同じ出力事象が起きる確率の差を制限する保証です。個人の影響をゼロにするものではなく、集団の傾向などから個人の属性を推論することまで禁止しません。保証の強さと結果の有用性を併せて評価します
- **④連合学習**: **連合学習(federated learning)**は、生データを各所に置いたまま学習し、モデルの更新情報を共有する手法です。生データを中央へ集めない構成でも、更新情報から学習データが漏れたり、完成モデルから参加・属性を推測されたりする可能性があります。更新の共有先・集約方式・公開モデルを含む脅威モデルが必要です
- **⑤秘密計算・TEE**: 暗号を使って計算する秘密計算と、信頼された実行環境(TEE: Trusted Execution Environment)で処理を隔離する技術です。暗号方式・ハードウェアへの信頼・保護する処理段階が異なり、一律に「最も強力」とは選べません。性能と運用費用も含めて比較します

差分プライバシーを採用するときは、次の 3 点を仕様にします([NIST SP 800-226](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-226.pdf))。

- **保護単位**: 1 行・1 イベント・1 人の全記録のどれを変更した隣接データセットで保証するか。1 人が多数の会話を持つ場合、1 行の保護をその人全体の保護と取り違えません
- **ε・δ**: 隣接するデータセット `D`・`D'` と出力事象 `S` について、機構 `M` が `P[M(D) ∈ S] ≤ exp(ε) × P[M(D') ∈ S] + δ` を満たすように設計します。乗法の係数は `exp(ε)`、加法の許容分は `δ` です。同じ定義・条件では小さいほど強い制約ですが、結果の有用性も評価します。単に「ノイズを入れた」だけでは保証になりません
- **プライバシー予算(privacy budget)**: 同じ対象に対する複数回の集計・公開では、保証を合成して累積の ε・δ を管理します。単純な逐次合成なら各公開の ε と δ の和が上限になります。各回が適合していても、公開回数を無制限に増やしてよいわけではありません

連合学習では、更新情報への攻撃に対して安全な集約(secure aggregation)や差分プライバシーを組み合わせる選択肢があります。ただし集約時の秘匿だけで完成モデルからの推論も防げるとは扱わず、誰から何を保護するかを分けます([NIST の連合学習への攻撃解説](https://www.nist.gov/blogs/cybersecurity-insights/privacy-attacks-federated-learning))。

### 成熟度と適用場面

各技術は、「**集計・学習・推論のどこに効くか**」で使い分けます。

- **集計・分析**: 統計・レポートを公開するなら、差分プライバシーで保護単位ごとの寄与による出力確率の差を制限できます。既存の非保護の公開や、集団の傾向からの推論まで無効にする保証ではありません
- **学習**: 生データを集められない要件があるなら、連合学習が候補です。更新情報を送ること自体の許容範囲と漏えい対策も確認します([ファインチューニングと蒸留](../03-implementation/fine-tuning-and-distillation.md)の学習側)
- **推論・処理全般**: データを暗号化・隔離したまま扱う必要があるなら、秘密計算・TEE が候補ですが、コストが高く適用は限定的です
- **成熟度は一様でない**: 検出・マスキング・匿名化は広く実用され、差分プライバシーは集計で実用例があり、連合学習・秘密計算は適用場面が特定的です。「新しくて強力」でも、自社の場面で現実的かは別です

### 高度な技術より先にやること

PET の実務で最も重要な原則は、**高度な技術に飛びつく前に、基本を尽くす**ことです。

- **データ最小化**: 不要なデータを**集めない・持たない・保持しない**ことで、自組織から漏れる対象を減らします。処理に必要な情報と、保存せずに扱える情報を分けます([AI のためのデータガバナンス](../05-operations/data-governance-for-ai.md))
- **アクセス統制**: 集めたデータへのアクセスを、必要な人・用途に絞ります([マルチテナント設計とテナント分離](../02-architecture/multi-tenancy-and-isolation.md)・[会話データの管理基盤](../05-operations/conversation-data-management.md))。閲覧者の制限と、公開結果からの推論に対する保護は役割が異なります
- **検出・マスキング**: 対象データで検出漏れ・過剰マスキングを評価し、残る情報で再識別される可能性も確認します。満たせない要件があれば追加の PET を検討します
- **要件に合わせて組み合わせる**: 最小化・アクセス統制・マスキングの検討を省略しません。ただし公開統計の保護など、これらだけでは満たせない要件があれば、差分プライバシー等も最初から併せて設計します

### 選定の判断フレーム

PET を選ぶときの判断は、次の順で行います。

1. **要件を特定する**: 何を・誰から・なぜ守るか(規制要件・データ主権・機微度)を明確にします
2. **基本で足りるか**: データ最小化・アクセス統制・マスキングで要件を満たせないかを、まず検討します
3. **場面に合う技術を選ぶ**: 足りない場合、集計なら差分プライバシー、集められない学習なら連合学習、と場面に合わせます
4. **コストと現実性を測る**: 精度低下・性能コスト・実装/運用の負担を見積もり、現実的かを判断します。「導入できるが割に合わない」を避けます

## 実務での注意点

### アンチパターン

- **高度な PET に飛びつく** → コストばかり高く、基本(最小化・統制)が抜ける → データ最小化 → アクセス統制 → マスキングを先に尽くす
- **「匿名化したから安全」と考える** → 他データとの突き合わせで再識別される → 再識別の限界を前提に、アクセス統制と併用する
- **差分プライバシーの精度低下を見ずに導入する** → 結果の有用性が落ちて使えない → プライバシーと精度のトレードオフを測って判断する
- **差分プライバシーなら個人について何も推論できないと考える** → 保護単位・累積公開・集団からの推論の違いを見落とす → ε・δ と保護単位、公開全体の予算を仕様にする
- **連合学習ならデータは漏れないと考える** → 更新情報や完成モデルからの攻撃を見落とす → 集約時と公開後を分け、必要な追加保護を設計する
- **場面に合わない技術を選ぶ** → 集計問題に連合学習を持ち込む等のミスマッチ → 集計・学習・推論のどこに効くかで選ぶ
- **要件を特定せず技術ありきで進める** → 守るべきものが曖昧なまま投資する → 何を・誰から・なぜ守るかを先に特定する

### チェックリスト

- [ ] 守るべき要件(規制・データ主権・機微度)を特定した
- [ ] データ最小化(そもそも集めない・持たない)を先に検討した
- [ ] アクセス統制で「誰が見られるか」を絞っている
- [ ] 検出漏れ・過剰マスキング・文脈からの再識別リスクを評価している
- [ ] 匿名化の再識別の限界を理解し、過信していない
- [ ] 高度な PET は、場面(集計/学習/推論)に合うものを選んでいる
- [ ] 差分プライバシーの保護単位・ε・δ・累積のプライバシー予算を確認した
- [ ] 連合学習の更新情報・完成モデルからの漏えいを脅威モデルに含めた
- [ ] 精度低下・性能・運用コストを測り、現実的かを判断した
