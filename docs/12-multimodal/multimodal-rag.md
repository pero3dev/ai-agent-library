# マルチモーダル RAG

## この記事の目的

画像・図表・PDF を含む知識源で RAG を組む際の、**2 つの索引方式と取得後の読解方式**を組み合わせられるようになります。テキスト化した索引・マルチモーダル埋め込みによる索引と、取得したページ画像の VLM 読解のトレードオフを理解し、図表の根拠提示・ハイブリッド・評価を設計します。テキスト RAG の原則は [RAG 実装パターン](../03-implementation/rag-implementation-patterns.md) が正本で、本記事はその**マルチモーダル差分**に絞ります。

## 対象読者

- 図表・帳票・スライドを含む知識源で RAG を組む必要があり、テキスト RAG では取りこぼす実装担当
- 既存のテキスト RAG に画像・PDF を取り込む拡張を検討しているエンジニア

## 前提知識

- [RAG 実装パターン](../03-implementation/rag-implementation-patterns.md) — テキスト RAG の原則(本記事はそのマルチモーダル差分)
- [埋め込み(embeddings)の選定と運用](../03-implementation/embeddings.md) — ベクトル検索の土台
- [ドキュメント AI(帳票・PDF の構造化)](document-ai.md) — 文書をテキスト化する前段(構成①の要)

## 本文

### 概要: 差分は「画像をどう検索可能にするか」

**マルチモーダル RAG(multimodal RAG)**は、テキスト以外(画像・図表・PDF ページ)を含む知識源で検索拡張生成を行う RAG です。テキスト RAG の原則(チャンク・検索・生成・評価)は [RAG 実装パターン](../03-implementation/rag-implementation-patterns.md) が正本で、本記事の差分は 1 点 — **画像・図表をどう検索可能にし、どう根拠として返すか**です。以下、索引方式と回答時の読解方式を分け、組み合わせ方を扱います。

### 索引と読解の構成要素・トレードオフ

①②は検索用の索引方式、③は検索後の読解方式です。三者は排他的な選択肢ではなく、①または②で検索した候補を③で読む構成にできます。以下の比較は独自の設計整理です。

| 構成要素 | 処理 | 強み | 注意点 |
| --- | --- | --- | --- |
| ①テキスト化して索引 | ドキュメント AI で画像/PDF をテキスト化し、通常のテキスト RAG に載せる | 既存テキスト RAG を流用できる | テキスト化で失う情報(図・レイアウト)がある |
| ②マルチモーダル埋め込みで直接検索 | クエリと画像ページの表現を照合して検索 | テキスト化を介さず画像を検索できる | 埋め込みの質・運用が難しい |
| ③検索候補を VLM で読解 | ①②などで選んだページ画像を VLM に渡して回答 | レイアウト・図を根拠にできる | 候補ページ数・解像度に応じた推論費用と誤読の評価が必要 |

- **①テキスト化して索引**: 既存のテキスト索引を活用する候補です。[ドキュメント AI](document-ai.md)で画像・PDF をテキスト化し、既存のテキスト RAG に載せます。抽出結果や既存基盤を流用できる一方、**図・グラフ・レイアウト**の情報はテキスト化で失われます。文字情報が主なら、抽出品質と索引費用を測る出発点にできます
- **②マルチモーダル埋め込み**: テキストクエリと画像ページの埋め込みを照合して検索します。単一ベクトルの方式だけでなく、[ColPali](https://arxiv.org/abs/2407.01449)のように複数ベクトルを照合する方式もあります([埋め込み](../03-implementation/embeddings.md))。テキスト化を介さず図表を引ける一方、埋め込みの質・評価・運用の難易度が上がります
- **③ページ画像を VLM で読む**: ページを画像のまま保持し、検索で絞った候補ページを VLM に読ませて回答します([画像理解の実務パターン](vision-understanding-patterns.md))。レイアウト・図をそのまま活かせますが、費用と待ち時間は主に読み取る候補ページ数・解像度・モデルで変わります。知識源全体が大きいことだけでは採用可否は決まりません
- **選び方**: 文字を検索に使うなら①、画像表現を検索に使うなら②を比較し、候補のレイアウトや図を回答根拠にするなら③を組み合わせます

### 図表の引用・根拠提示

マルチモーダル RAG の価値の 1 つは、**該当箇所を画像で示せる**ことです。

- **画像で根拠を返す**: テキストの引用に加え、「この図の・このページの・この領域」を画像で提示できると、利用者が根拠を確認しやすくなります。数値・図の解釈は特に、元画像を見せる価値が高いです
- **出典の粒度**: どのページ・どの図が根拠かを、回答と対応づけて返します。テキスト RAG の出典提示([RAG 実装パターン](../03-implementation/rag-implementation-patterns.md))の画像版です
- **幻覚対策になる**: 根拠画像は利用者による誤読の発見を助けますが、提示するだけで発見を保証しません。回答と画像の対応や数値の読解を別途評価します([画像理解の実務パターン](vision-understanding-patterns.md)の幻覚対策)

### ハイブリッド構成

検索と読解を**組み合わせる**構成例を示します。必要な品質と費用によって、単一の索引方式で十分な場合もあります。

- **テキスト + 画像の併用索引**: 文書をテキスト化した索引(①)と画像表現の索引(②)を併用し、検索候補を必要に応じて③で読みます。テキスト検索だけで必要なページを得られる場合は、①と③の組み合わせでも構成できます
- **2 段構え**: テキスト検索で候補を絞り(安価)、重要な図表を含む候補だけ VLM で読む(高価)、という段階設計でコストを抑えます
- **知識源の性質で配分**: 文字主体・図表主体のそれぞれで①②の検索再現率を比較し、候補画像の読解が必要なら③を組み合わせます

### 評価: 検索と読解を分離する

マルチモーダル RAG の評価は、**検索と読解を分けて**測ります。テキスト RAG の評価に、視覚の失敗モードが加わるためです。

- **検索の評価**: 正しいページ・図表が検索で上位に来るか(検索の再現率・精度)。テキスト RAG の検索評価([RAG 実装パターン](../03-implementation/rag-implementation-patterns.md))と同じ考え方です
- **読解の評価**: 検索できた画像を、VLM が正しく読めているか([画像理解の実務パターン](vision-understanding-patterns.md)の視覚タスク評価)。「正しい図を引いたのに数値を誤読」を切り分けます
- **分離の理由**: 検索と読解を混ぜて測ると、失敗の原因が分かりません。「検索が悪いのか、読解が悪いのか」を分けることで、どちらを直すかが決まります([Agent 評価の基礎](../04-evaluation/agent-evaluation-basics.md))

## 実務での注意点

### アンチパターン

- **候補を絞らず全ページを VLM に渡す** → 推論費用・待ち時間や入力上限が問題になる → ①②などで検索し、必要なページを③で読む
- **テキスト抽出で失われた情報を無視する** → 図・レイアウトに依存する問いで根拠が欠ける → ①②で必要なページを検索し、画像情報が必要な候補は③で読解して根拠を提示する
- **根拠画像を返さない** → 図表の誤読を利用者が確認しにくい → 該当ページ・図を画像で根拠提示する
- **検索と読解をまとめて評価する** → 失敗の原因(検索 or 読解)が切り分けられない → 検索の評価と読解の評価を分離する
- **テキスト RAG の原則を無視して作り直す** → チャンク・出典・評価の基礎を再発明する → テキスト RAG の原則を土台に、マルチモーダル差分だけ足す

### チェックリスト

- [ ] 知識源と質問の性質に合わせて索引①②を選び、必要な読解③を組み合わせた
- [ ] 図表の問いで必要なページを①②で検索でき、必要に応じて③で読解・根拠提示できることを評価した
- [ ] コストのため、テキスト検索で絞ってから VLM で読む段階設計を検討した
- [ ] 該当ページ・図を画像で根拠提示している
- [ ] 検索の評価と読解の評価を分離して測っている
- [ ] テキスト RAG の原則(チャンク・出典・評価)を土台にしている
