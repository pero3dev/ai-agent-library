# P3: モデル横断・MCP・評価の基礎

## 作業契約と方針

- 「モデル間の違いと移行」「MCP」「Agent評価の基礎」の3記事を選び、共通と固有の差分、接続方式と権限、測る対象と採点・反復の基準を図にする。文章・具体例の増量を目的にしない。
- 専用モデル・本文対応・SVG・包装・登録・MDX許可・固有検査、本記録と索引・引き継ぎを所有する。既存の表・式・例・確認日・未確認を保持する。
- 最新の実マージ済みmainから通常PRを提出し、前単位の公開表示後にマージする。通常PR・必要検査・必須CI・squash・既存Pagesは依頼で許可済み。任意レビュー・追加台帳・大量証跡を省き、公開後は表示確認のみ。

| 記事 | 主要論点の割当 | 保持する境界 |
| --- | --- | --- |
| 横断移行 | 普遍的な骨格と記法・役割・例・思考・出力・sampling・長文・強調の比較、世代差と非互換、トークン予算・回帰・管理するバリアント | 1つのtemperature・思考値を全社へ送らず、原文の確認時点を現行全モデルに広げず、リクエスト受理を品質にしない |
| MCP | N×Mとhost／client／server、プリミティブ、新旧方式と仕様／SDK、MRTRと複数レプリカの鍵・旧session、実stdio／mock／HTTP、業務とprotocolのエラー、選択・供給元・最小権限 | SDK更新を全仕様対応、stdioをHTTP認可、新仕様を鍵や通知の不要、tool説明と結果を実行権限にしない |
| 評価基礎 | 非決定性・自由経路・開放出力・多段、outcome／trajectory／component、コード・judge・人、実失敗から期待条件を作る、4部品、any／allの反復、品質と費用・遅延・投資段階 | デモと公開順位を自タスク品質、平均値を原因説明、judgeを無検証な正解にしない。模式の成功数は実Agent測定にしない |
